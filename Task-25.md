# Task 25

## Что сделано

Реализован мини-чат CLI поверх текущего RAG-пайплайна.

Чат:

- хранит историю диалога в памяти;
- при наличии `--history-file` загружает и сохраняет историю в JSON;
- на каждом новом сообщении строит retrieval query с учётом текущей задачи;
- ищет контекст в SQLite-индексе через improved RAG;
- отвечает через существующий RAG-agent с обязательными источниками и цитатами.
- распознаёт служебные реплики вроде приветствия, благодарности и короткого подтверждения, не записывает их как цель задачи и не запускает для них RAG-поиск.
- маршрутизирует пользовательские сообщения по типам `SMALL_TALK`, `TASK_SETUP`, `CONSTRAINT_UPDATE`, `CLARIFICATION`, `RAG_QUESTION`, `OUT_OF_SCOPE`.
- устойчиво читает русский ввод из терминала: сначала пробует UTF-8, затем fallback-кодировки вроде CP1251, а также исправляет типичный mojibake вида `РџСЂ...`.

RAG-поиск запускается только для `RAG_QUESTION`. Постановка цели, уточнения и ограничения обновляют память задачи и возвращают локальный структурированный ответ без обращения к retrieval.

При прогоне `--scenario` CLI печатает текст текущего пользовательского хода до вызова RAG/LLM, чтобы было видно, какой вопрос выполняется, даже если генерация ответа занимает время.

## Dialogue agent

Добавлен:

```text
rag/qa/dialogue_agent.py
```

Dialogue agent принимает текущее сообщение, `task_state` и недавнюю историю, затем выбирает действие:

- `LOCAL_REPLY` - ответ без RAG для служебной реплики;
- `UPDATE_TASK_STATE` - обновить цель, ограничения или уточнения;
- `RAG_ANSWER` - обычный вопрос к индексу;
- `SYNTHESIZE_WITH_RAG` - итоговый/плановый ответ по цели, истории и RAG-контексту;
- `OUT_OF_SCOPE` - явно вне индекса.

Для `SYNTHESIZE_WITH_RAG` retrieval query строится не из слов вроде `вернись к цели`, а из:

- цели диалога;
- уточнений;
- ограничений;
- терминов;
- последних пользовательских ходов.

Пример:

```text
Теперь вернись к цели диалога и перечисли пошаговый план реализации.
```

выбирает `SYNTHESIZE_WITH_RAG` и ищет факты для плана реализации по сохранённой цели.

## Память задачи

Добавлен:

```text
rag/qa/chat.py
```

Task state хранит:

- цель диалога;
- уточнения пользователя;
- ограничения;
- зафиксированные термины.

Память обновляется детерминированно из пользовательских сообщений и передаётся в prompt как контекст диалога. Репозиторные факты по-прежнему должны подтверждаться retrieved chunks.

## Маршрутизация сообщений

Добавлен:

```text
rag/qa/message_router.py
```

Примеры:

- `Привет!` -> `SMALL_TALK`;
- `Цель диалога: подготовить объяснение архитектуры Now in Android` -> `TASK_SETUP`;
- `Цель диалога: хочу понять, как безопасно добавить новую фичу в стиле Now in Android.` -> `TASK_SETUP`;
- `Нужно больше узнать про устройство приложения now android` -> `CLARIFICATION`;
- `отвечай кратко и лаконично` -> `CONSTRAINT_UPDATE`;
- `Под data layer я имею в виду репозитории` -> `CLARIFICATION`;
- `Собери итог: цель всё ещё объяснить архитектуру команде, дай короткую структуру доклада.` -> `RAG_QUESTION`;
- `Что нужно добавить для новой фичи?` -> `RAG_QUESTION`;
- `Какие архитектурные ограничения проекта нужно учитывать?` -> `RAG_QUESTION`;
- `Какие архитектурные слои используются?` -> `RAG_QUESTION`.

Маршрутизатор учитывает границы слов для фразовых маркеров: например, `мне нужно` больше не матчится как ограничение `не нужно`.
Цель диалога обновляется только при явной постановке через маркеры вроде `цель`, `цель диалога`, `задача`. Фразы с `нужно`, `хочу`, `выяснить` без явного маркера цели сохраняются как уточнения и не перезаписывают `goal`.
Команды ответа вроде `начни`, `собери`, `дай`, `подготовь`, `сформируй`, `резюмируй` классифицируются как `RAG_QUESTION`, даже если внутри есть напоминание о цели.
Явная цель в начале сообщения имеет приоритет над маркерами уточнения: слово вроде `добавить` внутри цели больше не переводит сообщение в `CLARIFICATION`.
Явный знак `?` имеет приоритет над маркерами уточнений и ограничений, кроме сообщений с явной постановкой цели вроде `Цель диалога: ...`.
